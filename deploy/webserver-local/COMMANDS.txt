 2. BUILD & DEPLOY (on this server)
--------------------------------------------------------------------------------
 cd C:\Apps\PUGHoldingWebSite-Docker

 # Normal build + start
 docker compose -f docker-compose.webserver-local.yml up -d --build

 # Flaky internet? Build ONE image at a time (less RAM, less impact on the
 # live app) and auto-retry until it finishes. The pip/npm cache mounts make
 # each retry RESUME instead of re-downloading.            [PS]
 do { docker compose -f docker-compose.webserver-local.yml build backend }  until ($LASTEXITCODE -eq 0)
 do { docker compose -f docker-compose.webserver-local.yml build frontend } until ($LASTEXITCODE -eq 0)
 docker compose -f docker-compose.webserver-local.yml up -d

 # One-time shared network (already created; only if it's ever missing)
 docker network create pug_edge

 # Confirm both stacks share the edge network (should list nginx + the 2 pugweb-*)
 docker network inspect pug_edge --format "{{range .Containers}}{{.Name}} {{end}}"

 6. BACKUP — PostgreSQL (custom-format .dump, same kind you restored)
--------------------------------------------------------------------------------
 # Dump inside the container, then copy the file out to the host.
 docker exec pugweb-postgres-1 pg_dump -U pug_user -Fc -f /tmp/pug_backup.dump pug_holding
 docker cp pugweb-postgres-1:/tmp/pug_backup.dump .\pug_backup_pug_holding.dump

 # Timestamped filename:                                    [PS]
 docker exec pugweb-postgres-1 pg_dump -U pug_user -Fc -f /tmp/pug_backup.dump pug_holding
 docker cp pugweb-postgres-1:/tmp/pug_backup.dump ".\pug_backup_pug_holding_$(Get-Date -Format yyyyMMdd_HHmmss).dump"

 # Uploads (only if you store media on local disk instead of Cloudflare R2)
 docker cp pugweb-backend-1:/app/uploads .\pug_uploads_backup


--------------------------------------------------------------------------------
 7. RESTORE — PostgreSQL  (THE SEQUENCE THAT WORKED)
--------------------------------------------------------------------------------
 cd C:\Apps\PUGHoldingWebSite-Docker

 REM 1) Copy the .dump into the postgres container (plain docker cp, NOT compose cp)
 docker cp "pug_backup_pug_holding_20260601_132100.dump" pugweb-postgres-1:/tmp/restore.dump

 REM 2) Stop the app so nothing holds DB connections during the restore
 docker stop pugweb-backend-1

 REM 3) Recreate the DB and restore the dump into it
 docker exec pugweb-postgres-1 psql -U pug_user -d postgres -c "DROP DATABASE IF EXISTS pug_holding;"
 docker exec pugweb-postgres-1 psql -U pug_user -d postgres -c "CREATE DATABASE pug_holding OWNER pug_user;"
 docker exec pugweb-postgres-1 pg_restore --no-owner --no-privileges -U pug_user -d pug_holding /tmp/restore.dump

 REM 4) Start the app again (runs alembic upgrade head to catch up if needed)
 docker start pugweb-backend-1

 # If "DROP DATABASE ... is being accessed by other users": kill connections, retry step 3
 docker exec pugweb-postgres-1 psql -U pug_user -d postgres -c "SELECT pg_terminate_backend(pid) FROM pg_stat_activity WHERE datname='pug_holding';"

 # If pg_restore says "input file does not appear to be a valid archive" the
 # file is plain SQL, not custom format -> use psql instead of pg_restore:
 docker exec pugweb-postgres-1 psql -U pug_user -d pug_holding -f /tmp/restore.dump

 10. TROUBLESHOOTING (issues we actually hit, and the fix)
--------------------------------------------------------------------------------
 * Build fails: "Read timed out" / "No matching distribution" (flaky PyPI/npm)
     -> Re-run the build; cache mounts resume. Use the per-image retry loop
        in section 2. Or build on another PC (section 3).

 * Live accommodation site slows/goes down WHILE building PUG web
     -> Resource contention, not a conflict. Give Docker Desktop 6-8 GB RAM,
        build one image at a time, or build off-peak / on another machine.

 * Cloudflare 502 "Bad gateway / Host Error" on parisunitedgroup.com
     -> nginx can't reach the app. Check nginx is on pug_edge (section 8) and
        the PUG stack is up (section 1).

 * nginx container keeps Restarting / "docker exec ... is restarting"
     -> Bad baked config. See why:
          docker logs pug-accommodation-prod-nginx-1 --tail 30
        Common causes we saw:
          - "[www...](https://...)" Markdown link artifacts pasted into nginx.conf
          - "proxy_http_version directive is duplicate" (don't re-declare a
            directive that the proxy-common.conf snippet already sets)
        Fix nginx.conf, then rebuild:
          docker compose -f docker-compose.prod.yml up -d --build nginx

 * "no container found for service postgres" on `docker compose cp`
     -> You omitted -f (it used the wrong compose/project). Use plain docker:
          docker cp <file> pugweb-postgres-1:/tmp/...
        or add  -f docker-compose.webserver-local.yml  to the compose command.

 * "wget: bad address 'pugweb-backend:8000'"
     -> Wrong name. On pug_edge the backend's alias is pugweb-api (not
        pugweb-backend). Use pugweb-api:8000. Container name is pugweb-backend-1.

 * Admin login calls http://localhost:8000 / fonts blocked
     -> Frontend image built with the wrong public URL. Rebuild frontend:
          docker compose -f docker-compose.webserver-local.yml build --no-cache frontend
          docker compose -f docker-compose.webserver-local.yml up -d
